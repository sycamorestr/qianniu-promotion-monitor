# 千牛推广巡检 · Playwright 版

本技能自带浏览器控制与业务适配，不依赖工作台、开票技能或 OpenCLI。以私有 `shops.json` 登记店铺和浏览器配置，也可直接沿用已有工作台登记。当前支持 Windows 上的原生 Edge/Chrome；进程归属和正常关闭核验使用 Windows 能力，不能将 macOS/Linux 或任意 CDP 浏览器视为已支持。

默认按店启动或复用 → 巡检及授权操作 → 保存结果与会话 → 正常关闭并确认退出。已有外部管理的浏览器需要保持运行时，在新批次使用 `--connect-only --keep-browser`。运行器为一次性进程，无需常驻代理。

## 执行入口

使用 `scripts/run_batch.py`；单店也通过 `--shops <店铺id>` 运行。首次接入、配置迁移或恢复时读[运行与恢复](references/runbook.md)，解释阈值、修改适配器或核对结果口径时读[业务规则](references/business-rules.md)。

```powershell
& $python "$skill/scripts/run_batch.py" `
  --registry "$work/shops.json" --config "$work/promotion-config.json" `
  --mode report --output-root "$work/outputs"
```

变量设置、独立接入模板、相对路径、浏览器选择及本地检查见[准备环境](references/runbook.md#准备环境)。需要 Python 3.11 及以上和 `requirements.txt` 中的 Playwright；不需下载 Playwright 专用浏览器。省略 `--date` 使用北京时间当天，历史巡检明确传入日期。

按本次用户意图选择模式：

| 模式 | 行为与授权 |
| --- | --- |
| `report`（默认） | 只读巡检并保存本地结果，不发通知、不暂停 |
| `dry-run` | 用户已要求发企业微信提醒时使用；发送巡检与待暂停清单，不暂停 |
| `execute` | 用户已明确授权暂停符合规则的计划时使用；写前复核、逐条暂停、写后定向核验。只有暂停授权时加 `--no-notify`；同时有通知授权时每次批次处理结束发送一次汇总 |

创建或迁移技能、检查登录、生成报告不代表暂停或发消息授权。已有明确授权时直接执行相应模式，无需反复确认。启用通知时读取本技能根目录 `config.json` 的 `wechat_webhook_url`，初次配置见运行说明；`--config` 只指定业务阈值与请求限制。通知凭据不进入报告、日志、审计或命令行参数。

## 店铺循环与身份

- 独立登记只需 `shops.json`。同目录存在 `.browser-workbench-shops.json` 时兼容合并，不为已登记店铺另建 Profile。省略 `--shops` 时处理全部登记；显式指定时按参数顺序执行。新批次冻结选中店铺、顺序、日期、阈值及浏览器身份。
- 工作台登记可能包含票据等非店铺工具，登记存在不代表纳入推广授权。遵循用户及项目的用途范围，必要时由项目入口从原登记选择店铺并显式传 `--shops`，不要复制独立店铺清单。显式选择后仅加载、校验所选店铺的浏览器配置；`check.py --shops` 使用相同范围。旧批次冻结范围若含用户排除的环境，不直接恢复或手改身份。
- 每店使用独立 `user_data_dir` 和固定非零 CDP 端口；持有数据目录锁时才控制浏览器。登记目录的 `.promotion-monitor.lock` 防止整轮并行，数据目录锁协调共享该目录的任务。锁等待到期、端口冲突或归属不明时报告原问题，不删除锁、换端口、换目录或循环重启。
- 浏览器配置 `lock_wait_seconds` 可设 0–120 秒，巡检默认 5 秒，仅用于启动或连接前等待目录互斥锁，不重放业务查询或暂停请求。到期后只有确认本次尚未启动或连接时才记录该店未执行、继续其他店铺，并保留待复核状态。真实会话保存或关闭失败仍停止整轮；新的锁占用不能抹掉恢复时已有的未决收尾。
- 仅有 `home` 角色也可接入，运行时在内存中补入推广页角色，不改写原配置。`--connect-only` 仅禁止启动进程，`--keep-browser` 才保留窗口；两者可配合使用。
- 新批次冻结 `close_after_shop`，恢复不能更改；旧批次没有该字段时沿用保留浏览器的行为。会话保存或正常关闭失败时保留现场，不强杀，停止继续打开下一店并在报告中列出未执行店铺，避免失败浏览器持续累积。单店登录或指标异常在会话保存与关闭成功后可以继续下一店。
- 关闭前先保存业务结果并标记 `closing`，确认收尾后才算该店完成；关闭阶段中断的店铺恢复时不能作为成功店铺跳过。Ctrl+C 或取消会保存 `stopped`，取消清理期间不发送通知，之后可恢复或另行 `--finalize`。
- 以平台实际返回的阿里妈妈身份为准。显式填写 `expected_alimama_shop` 时始终严格核验实际店铺名；同时有 `login_username` 时再核验完整账号。未填真实店铺名但提供 `login_username` 时，业务查询前必须先精确核验页面运行时完整昵称，再绑定本轮实际 `shopName/nickName`，允许 `store` 保留工作台显示别名。两者都未提供时回退为 `store` 精确核验。不能填账号备注、按前缀匹配或推猜账号与店铺关系；页面存在或 URL 不含 login 都不是登录证明。
- 首次核验的实际店铺名与完整账号绑定两类推广、暂停和恢复，即使扫描为零条也持久化为 `scan_identity`。后续观察身份变化时停止，不用新观察值覆盖原绑定来放宽检查。
- 优先复用原登记浏览器的现有会话。启动或只读巡检确认登录失效后，若已配置飞书 Cookie 库，按本店精确取附件并在原浏览器恢复一次，核验完整账号后继续。恢复失败时按逐店审计处理。详见[登录失效处理](references/runbook.md#登录失效处理)。
- 验证码、风控、429、身份不符或身份信息缺失时停止本店操作，不输入账密、切换账号或绕过验证。暂停及写入结果未知不自动重放。
- 更换电脑或修改已冻结的浏览器路径、配置时创建新批次；旧批次不跨环境续写，不手改身份或检查点。新环境需要核验店铺身份，可使用人工登录或已配置的飞书会话恢复。

## 巡检与暂停约束

默认仅巡检活动计划：低 ROI 提醒为 `ROI < 2`，暂停候选为 `花费 > 30 且 ROI < 1.5`，均为严格比较；业务阈值以本轮冻结配置为准。ROI 和花费的空值按 0 参与判断：ROI 空且花费大于 30 时需要暂停，花费空则不满足暂停条件。

报告显示两位小数，阈值使用原始数值精度，空值显示为 0。即使整类计划的 ROI、花费都为空，也按零值正常处理，不报指标缺失、不计缺失数量、不因此标记 `needs_review` 或阻止同店其他候选暂停。非空非法指标、登录、身份、接口与响应结构错误仍按真实异常处理。

扫描显式使用本轮报表日期，省略 `--date` 时取 Asia/Shanghai 当天。暂停沿用扫描记录的 `reportContext`；恢复先按原候选 ID 定向核验，再使用核验返回的最新上下文。不能从持久页面残留的日期推断本轮口径。

每次写入前重新核对店铺、计划 ID、活动状态、日期和指标。只处理本轮候选；执行后逐 ID 核验，列表缺失、筛选未生效、查询失败都不是暂停成功证据。暂停结果未知时保留“待核验”，不自动重放写请求。同店其他计划在身份有效时仍可逐条独立处理。

“待暂停”指本轮按空值归零规则判断后符合条件的候选清单；“已暂停”是最终核验确认停用的子集。确认仍活动写“仍在推广”，无法确认写“待核验”，不将失败数或剩余数改称待暂停。

## 中断、恢复与交付

`--resume <原作业目录>` 先校验不可变检查点哈希并跳过成功店铺，只恢复未完成扫描、对未完成店铺的已有候选做只读定向核验，不自动重试暂停。确需重试时，先确认用户已有本轮执行授权，再准备逐目标的旧操作已结束证据，通过 `--retry-targets <JSON>` 明确选择目标；格式与边界见[运行与恢复](references/runbook.md#恢复和有限重试)。无法证明旧操作已结束时只核验，不重试写入；不要手改检查点或删除锁以绕过限制。

读取作业审计后继续处理未决问题，不将运行器退出等同于任务完成。新批次使用 `after_batch` 通知策略：正常处理结束，包括 `needs_review`、非取消导致的 `stopped`，按当前检查点快照发送一次汇总，必要时按企业微信长度拆条；通知保存实际文本。已发送但业务未完成的新批次可只读恢复，保留 `notification_history` 并在本次恢复结束后发送新汇总；已经 `complete` 的批次恢复时跳过，不重发。`pending` 且部分条目已送达时禁止恢复改写，只能 `--finalize` 续发冻结文本；尚未发送任何条目的 `pending` 可恢复后重建未发快照。`sending` / `delivery_unknown` 阻止重发和恢复；旧批次未记录策略时沿用原来的完成后发送规则。

`--finalize <原作业目录>` 仅发送保存的审计快照，不重新扫描、不执行暂停或重复已发送消息。`report` 或禁用通知的作业不发送；恢复时可用 `--no-notify` 单向关闭后续通知，不能重新启用。发送结果未知时先核对，避免重复消息。

交付 `report.md`、`batch-summary.json` / `.csv`、`batch-state.json` 和逐店审计等实际产物。`shops/<id>/checkpoints/<sha>.json` 是正式恢复依据，`audit.json` 是便于查看的副本。明确已完成、失败、未执行和待核验范围；未核验暂停不能列为已暂停。通知按店铺展示低 ROI 结果，最后给出集中暂停操作汇总；低 ROI、待暂停和已暂停条目均附计划 ID，本地报告采用相同格式。技术错误和恢复证据保存在本地。

## 维护与验收边界

维护入口是本目录 `scripts/` 与 `adapters/`；修改后按[本地验证与线上验收](references/runbook.md#本地验证与线上验收)运行对应测试，区分离线覆盖、本机浏览器验证与真实业务验收。测试数量、店铺数量和历次验收结果留在各次报告中，不作为跨机器能力保证。

保存会话不保证平台 session 永不过期，下一次仍重新核验身份。本技能不改工作台全局调度，也不保证其他已开窗口或工作台保活任务不占资源。分享包排除私有店名、配置、输出、Cookie、Webhook、浏览器数据目录和运行时登记；通知配置只分享 `config.example.json` 或地址为空的 `config.json`。
